# Candidate research contributions

1. A formal definition of Documentation-Driven Threat Analysis and its boundaries.
2. A methodology-neutral Base Analysis model derived from governed software documentation
   through an explicit candidate and review boundary.
3. A versioned methodology-plugin and overlay boundary that allows distinct threat-analysis
   methods to consume the same Base Analysis without moving method-specific semantics into the
   common core.
4. A common Finding boundary through which heterogeneous methodology results can be reviewed
   and compared without erasing their methodological provenance.
5. A governed path from accepted Findings to testable Security Requirements that become part
   of the project documentation while retaining end-to-end traceability.
6. A provenance and change-impact model for identifying analytical artifacts requiring
   re-evaluation after relevant source or methodology changes.
7. ThreatForge as a reference implementation and experimental instrument, demonstrated with
   STRIDE and STRIDE-AI plugins over the same core model.
8. A case-based evaluation protocol using explicit reference models and published or
   independently prepared expected results where suitable.

These are candidate contributions. The thesis does not claim universal methodology support,
economic benefit, or superiority over conventional threat modeling unless separately supported
by evaluation evidence.
