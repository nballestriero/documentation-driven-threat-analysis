# Working terminology

- **Governed documentation:** versioned project records with controlled structure, identity, lifecycle state, validation rules, and traceable relations.
- **DDTA portability / analysis-readiness contract (DDTA input contract):** the methodology-neutral contract whose satisfaction makes governed project documentation portable-by-construction for DDTA evaluation. It defines required common project knowledge, identities, relations, provenance, versioning and controlled extensibility, but must not encode methodology-owned threat semantics or case-specific expected results.
- **Portable-by-construction governed documentation:** governed project documentation intentionally authored to satisfy the DDTA input contract before threat analysis is executed.
- **Documentation-Driven Threat Analysis (DDTA):** a process in which portable-by-construction governed project documentation is the primary authority used to build and maintain a methodology-neutral analyzable representation, support progressive human understanding, execute methodology-specific analyses, and return reviewed corrective changes to governed documentation.
- **Base Analysis:** the accepted methodology-neutral analyzable representation of common project knowledge for a governed baseline. Its BA0-closed responsibility is to preserve baseline-scoped shared semantic identity, source/origin provenance and explicit unresolved state sufficiently for reproducible reuse, human/method projections, source drill-down, change-impact reasoning and source-localized feedback handoff. BA1 closes its minimal first-class semantic identity ontology as `BAReferent + BAProposition`; relation/action structure, provenance mechanics and projections remain BA2-BA6 responsibilities. Its canonicality is **semantic within the analysis layer**, not a requirement for one long-lived materialized graph or one storage technology.
- **BAE (Base Analysis Element):** umbrella term for semantic elements in Base Analysis. BA1 does not require `BAE` to be an additional first-class metaclass beyond the accepted `BAReferent` and `BAProposition` identity families.
- **BAReferent:** an independently identifiable unit of methodology-neutral shared project meaning reusable across analytical propositions, projections or governed baselines. A referent can denote structural, human/external, informational/resource, behavioral/event, contractual, storage, boundary, state/context or other project meaning without those categories automatically becoming separate first-class metaclasses. A BAReferent denotes analytical project meaning, not necessarily one runtime object instance.
- **BAProposition:** an independently identifiable methodology-neutral analytical assertion about one or more BAReferent identities. Proposition identity exists so origin/provenance, diagnosis, reuse and change disposition can be handled at assertion level without confusing the assertion with the project meaning it describes.
- **BA semantic kind / classification:** method-neutral classification or role information used to distinguish relevant kinds of BAReferent or proposition participation without automatically creating a dedicated first-class metaclass. Exact classification, role and relation vocabularies are downstream BA2/BA5 concerns and must not silently become method-specific categories.
- **Grounded analytical statement:** analytical project meaning directly supported by governed documentation and traceable to its source basis.
- **Derived analytical statement:** normalized analytical structure justified from governed meaning without introducing a new project commitment; it remains provenance-bearing and reviewable.
- **Diagnostic / unresolved state:** explicit representation that accepted analytical meaning cannot yet be justified because relevant evidence is conflicting, ambiguous, missing or insufficient. It must not be silently canonicalized.
- **Progressive view / teachability projection:** a derived, non-authoritative view that exposes the same accepted project knowledge at a bounded level of detail so that a human can move from overview to analytical detail and exact governed sources without creating a competing authored model.
- **Overlay:** a methodology-specific analysis applied without redefining Base Analysis semantics; examples planned for thesis evaluation include STRIDE and STRIDE-AI.
- **Candidate finding:** machine- or analyst-produced result not yet accepted as a research finding or product obligation.
- **Accepted finding:** candidate reviewed under an explicit protocol and accepted.
- **Corrective documentation candidate:** a source-localized proposal to clarify, correct, supersede or extend governed documentation. It has no project authority until accepted through the documentation governance process. Base Analysis supports provenance/localization of the handoff but does not own acceptance or the correction workflow.
- **Baseline:** immutable identity of the source repository state used by a study.
- **Stale result:** result whose supporting source or model dependencies changed after the analysis baseline and therefore requires review.
- **Projection:** a derived human- or method-oriented view, such as a project map or DFD; it is not itself the source authority and need not be the canonical materialization of Base Analysis.
- **Legacy/generic documentation migration:** transformation of arbitrary project documentation into DDTA-portable form; explicitly outside the current thesis evaluation and reserved for future work.
