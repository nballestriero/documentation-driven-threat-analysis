\section{Reworked parameter semantics}
The earlier A5 wording that placed exact values \texttt{10} and \texttt{50} directly inside FR identity was too strong. The stabilized distinction is between governed threshold/window semantics and concrete current bindings whose immutable normative status is not established.

\begin{ddtaexample}[title={Semantic parameters and current bindings}]
\textbf{Prompt evolution threshold.} \texttt{PromptEvolutionThreshold=N}; current documented binding \texttt{N=10}; exact-value governance and change authority \NS.\par
\textbf{Classifier adaptation threshold.} \texttt{ClassifierAdaptationThreshold=N}; current documented binding \texttt{N=50}; current realization may bind \texttt{RETRAINING\_THRESHOLD=50}; exact-value governance and change authority \NS.\par
\textbf{Prompt evidence window size.} \texttt{PromptEvidenceWindowSize=N}; current documented binding \texttt{N=20}; exact-value governance and change authority \NS.
\end{ddtaexample}

\begin{ddtaanti}[title={Do not parameterize away governed transformations}]
The mapping \texttt{P1/P2->HIGH, P3->MEDIUM, P4->LOW} is not analogous to \texttt{10/20/50}. Replacing its outputs with arbitrary variables destroys the governed functional meaning. The transformation remains inside FR-08.
\end{ddtaanti}

\section{Parameter Governance Boundary - GI-25}
\begin{ddtacore}[title={High-confidence candidate}]
DDTA should expose a parameter only when its semantic role materially affects governed behavior, constraints, lifecycle, acceptance or another analysis-relevant property. Crossing the boundary does not turn the parameter into a Requirement and does not require one document per parameter.
\end{ddtacore}

\begin{lstlisting}
concrete configuration value
        |
        v
neutralize value -> N
        |
        v
semantic role survives and is material?
   | NO                     | YES
   v                        v
realization/config STOP     exact value itself governed?
                            | YES       | NO / NOT SPECIFIED
                            v           v
                       preserve exact   DDTA semantic N
                       value            ---------------- boundary
                                        current concrete binding
\end{lstlisting}

Large configuration spaces remain in technical inventories. Tools may discover thousands of values automatically; DDTA should retain only the small subset that crosses the semantic boundary.
