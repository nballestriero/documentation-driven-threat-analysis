# FR-MR03-02-02 — Verifica dell'esistenza degli artefatti dichiarati dai FR

## Functional obligation

Verificare la risolvibilità dei binding dichiarati dai FunctionalRequirement verso le realizzazioni Python esistenti e riconoscere la presenza del riferimento inverso all'FR nel simbolo di codice.

## Normative clauses

- **NC-1:** Per ogni FR con claim `partial` o `implemented`, il controllo MUST verificare l'esistenza del file Python dichiarato, la presenza del simbolo di primo livello indicato e un riferimento `DDTA-FR` all'identificativo FR nella relativa docstring.
- **NC-2:** Un binding assente, non interpretabile, non contenuto nello scope del progetto, o che identifica un simbolo/riferimento diverso MUST produrre una diagnostica localizzabile e MUST NOT dare PASS al controllo di tracciabilità.
- **NC-3:** Il controllo MUST usare l'ID dichiarato dall'FR e MUST limitarsi agli FR nello scope; non deve dedurre binding da filename, posizione del file o testo di un assessment.
- **NC-4:** L'esito MUST distinguere il controllo formale degli artefatti dalla conformità funzionale: un binding esistente MUST NOT attestare la soddisfazione delle clausole normative, la copertura dei test o la correttezza della claim `implemented`.

- **NC-5:** Per ciascun riferimento `DDTA-FR` presente nella docstring di un simbolo Python incluso nello scope di controllo, il servizio MUST verificare che l'identificativo FR esista e che il medesimo FR dichiari un binding al simbolo; una dichiarazione orfana o riferita a FR inesistente MUST generare una diagnostica senza PASS.

## Riferimenti SPO e BA

La verifica riguarda riferimenti tra FR e codice, non identità o relazioni BA.

## Esempio di assessment (supporto di review, non normativa)

Un binding a file mancante, simbolo inesistente o privo di `DDTA-FR` fallisce; un binding valido supera soltanto il controllo formale di tracciabilità.
