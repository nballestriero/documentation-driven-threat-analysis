# FR-MR03-06-02 — Controllo bidirezionale fra casi di test e funzioni Python

## Functional obligation

Accertare che i casi di test dichiarati siano collegati a codice Python realmente esistente e che il codice dichiari un riferimento di ritorno coerente.

## Normative clauses

- **NC-1:** Il servizio MUST risolvere il `parentFunctionalRequirement` della TestSpecification e tutte le clausole `NC` citate dai suoi casi nello scope dichiarato; un parent o una clausola assente MUST produrre diagnostica.
- **NC-2:** Per ogni binding di caso, il servizio MUST accertare l'esistenza del file Python e del metodo di test dichiarato, e MUST verificare nella docstring `DDTA-TC: <ID-caso>` corrispondente.
- **NC-3:** Il servizio MUST verificare in direzione inversa che ogni funzione di test compresa nello scope selezionato dichiari esattamente un ID di caso risolvibile che la includa fra i suoi binding; una discordanza, duplicazione o associazione ambigua MUST impedire un PASS di tracciabilita per tale scope.
- **NC-4:** La validazione MUST rendere esplicito lo scope di verifica, distinguendo il controllo pilota delle sole TestSpecification dichiarate dal controllo globale di tutti i test. Un PASS pilota MUST NOT essere interpretato come copertura globale completata.
- **NC-5:** Il controllo strutturale MUST NOT certificare la qualita del test, la correttezza della sua logica o l'avvenuta soddisfazione dell'FR.

## Riferimenti SPO e BA

Il prototipo del controllo e `prototype/generic-v01/ddta_tool/test_trace.py::check_test_specifications`; il binding segnala una realizzazione **parziale**, non una conformita completa. Il controllo riusa il formato dichiarativo e la distinzione tra documenti normativi ed evidenze di verifica.

## Esempio di assessment (supporto di review, non normativa)

Una TestSpecification punta a `tests/test_ba_catalog.py::BACatalogTest.test_operator_catalog_consistency`; il metodo dichiara l'ID caso nella docstring. Se uno dei due riferimenti cambia indipendentemente, il controllo segnala una discordanza.
