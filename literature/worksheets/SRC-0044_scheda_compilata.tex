\section{1. Research problem and contribution}
Introduces AADL as a language with precise semantics and extensible properties for early/repeated architecture analysis, especially real-time and high-dependability systems. It models software, computational hardware and composite system components and supports mappings between application and execution platform.
\section{2. Starting artifacts and generated representations}
AADL component types expose features/ports; implementations contain subcomponents and connections. Execution-platform abstractions include processor, memory, bus and device. Modes represent configuration variants. Flow declarations and end-to-end flows are distinct from connections. Properties attach analysis-relevant values to components, ports and connections.
\section{3. Traceability, change, automation and human role}
AADL’s semantics are analyzability-oriented and permit partial specifications and repeated refinement. The report does not provide DDTA-style document provenance or governance; its contribution is a formal architecture representation that analysis tools can consume.
\section{4. Findings, limitations and relationship with DDTA}
It supports a generic “connection with properties” notion more strongly than a universal Channel root. Bus is a specialized communication platform component; memory is a specialized execution-platform component. Therefore Channel and Store are real system concerns but not necessarily top-level ontology primitives. It also shows that useful analysis can start before full implementation detail exists.
