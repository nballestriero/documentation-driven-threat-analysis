## Four reading questions

### 1. Research problem and contribution

Jackson argues for problem analysis that resists solution orientation. Problems are decomposed into subproblems of recognised classes represented by problem frames; each frame identifies domain structures/interfaces and a frame concern. The paper also catalogues recurring difficulties and composition concerns.

### 2. Starting artifacts and system representation

The starting artifact is a description of the real problem world: phenomena, domains, requirements, domain properties and the machine boundary/interface. Jackson distinguishes machine from problem domain and uses the adequacy relation machine specification + domain properties => requirement. Elementary frames are intentionally idealised; realistic problems need decomposition.

### 3. Traceability, change, automation and human role

The approach is analyst-led. It offers recognition/decomposition heuristics—outside-in, inside-out, different subproblem tempi and known composite frames—rather than an automated classifier. A crucial feature is that a near match can expose a 'difficulty' that becomes a separate subproblem instead of forcing the original frame.

### 4. Findings, limitations and relationship with DDTA / overlay

The paper provides a detailed worked package-router analysis and explicitly states limits: elementary frames do not encompass realistic problems, composition must be handled carefully, model domains must not be confused with the real world, and different subproblem descriptions can conflict. Particularly relevant to R23 is the 'identities difficulty': the machine may observe an event without having access to the roles/phenomena that identify the participating entity.

## Contribution

Primary formulation of problem frames/classes, recognition/decomposition heuristics, frame concerns and recurring problem difficulties.

## Findings

- Problem frames classify idealised recurring problem classes, not complete realistic projects.
- Near-matches can be decomposed by recognising separate connection/identity/etc. difficulties.
- An identities difficulty occurs when observable phenomena do not expose the identities/roles required by the requirement.
- Problem analysis should delay solution composition.

## Limitations stated by the authors / accessible source

- Conceptual/worked-example evidence rather than controlled empirical evaluation.
- Catalogue is explicitly non-exhaustive for realistic problems.

## Relationship with Documentation-Driven Threat Analysis

### Directly supported propositions

- A recurrent class should guide analysis, not replace the real problem description.
- A superficially close frame can fail on a material difficulty that deserves its own subproblem.
- Identity availability is a semantic property of the machine/world interface, not just a label choice.

### Tensions or contradictions

- Problem Frames includes a machine boundary and frame-specific modelling vocabulary; DDTA must not silently adopt that ontology as project authority.

### Research gap left open
