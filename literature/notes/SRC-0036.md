## Why this source is central

SRC-0036 supplies the contemporary multi-model comparison requested after SRC-0035. It evaluates
four LLMs on the same requirements-to-UML-class-diagram task and therefore narrows the risk of
attributing one historical model's behavior to all generative systems.

The study does not identify a universal winner. GPT-4o and Gemini produce no syntax errors in the
15 cases, DeepSeek has the lowest mean semantic-error count, Gemini has the highest mean
completeness, and Qwen is significantly worse on syntax. Most other pairwise differences are not
statistically significant.

The DDTA boundary is:

```text
natural-language requirements
-> shared role-based few-shot prompt
-> LLM web interface
-> candidate Apollon JSON / UML class diagram
-> syntax, coverage, semantic and trace validation
-> human correction and acceptance
```

The source therefore strengthens the rule established by SRC-0035:

```text
clear and renderable model
!= source-faithful accepted model
```

## Four reading questions

### 1. Research problem and contribution

Students and novice designers can find it difficult to derive correct and complete UML class
diagrams from textual descriptions. Earlier work suggested that LLMs can create reasonably
complete models but still fall short of human-made quality. This paper asks whether different LLM
architectures show different quality and error profiles when they solve the same exercises.

The research questions are:

1. whether different LLMs lead to differences in generated-diagram quality;
2. which error categories are produced by the different LLMs.

The contribution is a controlled comparison of GPT-4o, DeepSeek v3, Gemini 2.5 Pro and Qwen 3 using
one shared prompt and 15 exercises. Quality is decomposed into syntax errors, semantic errors and
completeness. The work is an exploratory educational study, not proof of autonomous or industrial
model construction.

### 2. Starting artifacts and system representation

The corpus contains 15 real university exercises from official teaching material at several Italian
universities. Each exercise asks for a UML class diagram from Italian natural-language requirements.
The domains include administrative, managerial, sanitary, educational, technical and general-purpose
applications.

The selection intentionally includes modeling difficulty:

- more than half of the descriptions contain ambiguity or implicit elements;
- at least one third contain explicit or implicit hierarchies;
- about two thirds contain composition or aggregation relationships.

The same role-based few-shot prompt is used without change for all four models. It instructs the
agent to behave as an expert in UML modeling and contains examples of textual requirements and JSON
diagram output. Models are accessed through free websites rather than APIs.

The transformation is:

```text
Italian textual exercise
-> expert-role few-shot prompt
-> GPT-4o | DeepSeek v3 | Gemini 2.5 Pro | Qwen 3
-> JSON compatible with Apollon
-> candidate UML class diagram
```

Four models applied to 15 exercises imply 60 evaluated diagrams. The paper does not state the
aggregate total explicitly, so 60 is a direct inference from the study design.

Apollon JSON is the target representation, not a neutral governed intermediate representation.
Extracted concepts, inferred relations, modeling decisions, omissions and unsupported additions are
not separated before the diagram is produced.

### 3. Traceability, change, automation and human role

#### Quality dimensions

The study uses three metrics:

- Syntax Errors;
- Semantic Errors;
- Diagram Completeness.

Completeness is the number of generated elements that match reference-solution elements divided by
the total number of reference elements. Classes, attributes, methods and relationships are matched
when names are considered sufficiently similar to represent the same concept.

Syntax errors include collection types used instead of associations, disconnected classes, missing
types or multiplicities, and references to other classes encoded as attributes. Semantic errors
include wrong method parameters or return types, wrong association types or multiplicities, and
wrong attribute types.

A methodological consequence is that semantic errors are counted only for elements already judged
to match the reference. An omitted element lowers completeness but may never enter the semantic-error
count. Completeness and semantic correctness must therefore remain separate.

#### Human evaluation

One author performs the initial manual evaluation. Two other authors independently review it, after
which the three combine feedback and agree on final results.

The paper does not report an inter-rater agreement coefficient, blinded evaluation, external
reviewers or a formal conflict-resolution protocol. Consensus mitigates but does not eliminate
subjectivity.

#### Traceability

The study links each generated diagram to one exercise and one reference solution through manual
comparison. It does not maintain assertion-level links between source sentences, extracted concepts,
UML elements, modeling decisions, errors and corrections.

```text
source assertion
-> proposed UML element or relation
-> independent source-coverage and semantic validation
-> accepted trace
```

This trace lifecycle is required by DDTA but is not implemented in the source.

#### Change

The study is one-shot. It does not test requirement modifications, incremental diagram updates,
stale detection, version comparison, decision retention or regeneration triggers.

#### Automation and human role

Generation is automatic after prompting. Corpus selection, prompt design, reference-solution choice,
matching, error classification, review and consensus remain human tasks. No measured correction
effort or accepted-model yield is reported.

### 4. Findings, limitations and relationship with DDTA

#### Descriptive results

| Model | Syntax errors mean | Semantic errors mean | Completeness mean |
|---|---:|---:|---:|
| GPT-4o | 0 | 4.33 | 64.2% |
| DeepSeek v3 | 0.13 | 3.00 | 58.3% |
| Gemini 2.5 Pro | 0 | 3.27 | 67.7% |
| Qwen 3 | 3.20 | 3.40 | 55.4% |

GPT-4o and Gemini have zero syntax errors across all 15 diagrams. DeepSeek has one syntax error in
two diagrams. Only one Qwen diagram has zero syntax errors.

DeepSeek has the lowest mean semantic-error count. GPT-4o has the highest. Gemini has the highest
mean completeness, followed by GPT-4o. Qwen never reaches 100 percent completeness.

#### Statistical interpretation

The clear significant result is Qwen's worse syntax performance relative to each other model. Most
semantic and completeness comparisons are not significant. The ChatGPT-DeepSeek semantic comparison
has `p = 0.086`, described by the authors as slightly significant without a declared alpha threshold.

The models should therefore be described as having different descriptive profiles, not as a stable
ranking. Model selection does not remove artifact-level validation.

#### Error categories and visual evidence

Figure 1 shows substantial overlap in completeness and semantic-error distributions. The strong
visual separation is Qwen's syntax distribution.

Figure 2(a) shows syntax errors concentrated in Qwen, especially:

- `collectionAttribute`: 27 Qwen errors;
- `foreignKeyAttribute`: 19 Qwen and 2 DeepSeek errors;
- `unconnectedClass`: 3 Qwen errors.

Figure 2(b) shows the following semantic counts:

| Category | GPT-4o | DeepSeek | Gemini | Qwen |
|---|---:|---:|---:|---:|
| methodAsAttribute | 2 | 2 | 1 | 1 |
| wrongAssociationOrder | 2 | 2 | 3 | 2 |
| wrongAssociationType | 35 | 11 | 19 | 14 |
| wrongAttributeType | 2 | 2 | 3 | 1 |
| wrongMethodInputParams | 0 | 1 | 0 | 0 |
| wrongMethodReturnType | 4 | 4 | 4 | 3 |
| wrongMultiplicity | 20 | 24 | 19 | 29 |

Association type and multiplicity are the dominant semantic error families. GPT-4o has the most
wrong-association-type errors; Qwen has the most wrong-multiplicity errors.

For DDTA, relationship errors can distort ownership, dependency, containment, privilege propagation,
trust boundaries and attack-surface reasoning. This security consequence is a researcher
interpretation; the paper does not evaluate threat analysis.

## Research method and corpus

The study follows a GQM framing with LLM usage as object, output comparison as purpose,
completeness/correctness as focus, class-diagram generation as context and software-modeling
educators as stakeholders.

RQ1 uses fixed-effect linear pairwise comparisons with model type as independent variable and the
three quality metrics as dependent variables. RQ2 aggregates errors by category and model.

The paper uses the term open-source for DeepSeek and Qwen. This note preserves that source wording
without independently asserting model-license terms.

## Limitations stated by the authors

### Internal validity

- possible evaluator bias despite two additional reviewers;
- no guarantee that the prompt is optimal;
- few-shot examples may cause overfitting;
- parts of the prompt may guide output suboptimally;
- different models may need different prompts.

### Construct validity

- the selected metrics may not be the most meaningful quality measures;
- additional error categories may exist;
- the completeness ratio may be too simple.

### External validity

- results may not generalize to other UML class-diagram formats;
- results may not generalize to other modeling notations.

## Limitations identified for DDTA comparison

- educational Italian cases rather than maintained industrial projects;
- class diagrams and functional requirements only;
- no security, privacy or other NFR model-generation evidence;
- no source-assertion-to-model-element traces;
- no explicit extracted-versus-inferred status;
- no change, version, stale-state or regeneration evaluation;
- web interfaces instead of controlled APIs;
- no immutable model snapshots, seeds or generation parameters;
- no repeated runs or output-variability analysis;
- no measured correction effort or accepted-model yield;
- reference-solution and name-similarity judgments remain partly subjective;
- no independent execution of the public companion package.

## Internal discrepancies and ambiguities

1. The text says ChatGPT and Gemini have approximately 65 percent average completeness for both,
   while Table II reports 64.2 and 67.7 percent.
2. The text describes DeepSeek and Qwen as approximately 55 percent, while Table II reports 58.3
   and 55.4 percent.
3. Table III prints completeness estimates with a percent sign, but the scale and unit are ambiguous.
4. The conclusion says there is only one significant result although three Qwen syntax pairwise
   comparisons are significant; these can be read as one underlying effect manifested in three tests.
5. Table III contains the label `DeepSeel - Qwen`.
6. The introduction contains `DeepDeek 3` and variable spellings of GPT-4o.
7. The abstract's statement that Qwen has similar completeness is broader than the descriptive means.
8. Descriptive rankings must not be overclaimed because most pairwise differences are not significant.

## Core definitions

### LLM-generated structural candidate

A class-diagram projection produced from selected textual evidence by a generative model. It is not
canonical project knowledge until its schema, syntax, source coverage, domain semantics and traces
have been independently reviewed.

### Structural semantic validation

Validation that classes, attributes, methods, hierarchies, association type, direction, containment
and multiplicity accurately represent the source and accepted domain knowledge.

### Generation provenance

The recorded provider, model and snapshot, interface/API, prompt, examples, parameters, session,
external context, timestamp, output schema and renderer that may affect the candidate.

## Nine documentation-first fields

1. Input and quality: Italian functional requirements with ambiguity, implicit elements, hierarchies and containment relations.
2. Compatibility: direct documentation input; no code required.
3. Intermediate representation: hidden interpretation inside each LLM; no governed neutral IR.
4. Procedure: prompt, generate Apollon JSON, compare to reference, count syntax/semantic errors and completeness.
5. Output: candidate UML class diagram.
6. Provenance, uncertainty and review: shared prompt and package exist; model snapshots and confidence semantics do not.
7. Evolution/change: not evaluated.
8. Evaluation/evidence: 15 exercises, four models, three metrics, pairwise analysis and category counts.
9. Thesis use: multi-model evidence for the candidate-model validation boundary.

## Directly supported propositions

- Four LLMs can generate partially complete UML class-diagram candidates from natural-language exercises.
- Model strengths vary across syntax, semantics and completeness.
- GPT-4o and Gemini can produce syntax-valid outputs in the evaluated cases while still making semantic errors.
- DeepSeek has the lowest descriptive mean semantic-error count in this corpus.
- Gemini has the highest descriptive mean completeness in this corpus.
- Qwen has significantly worse syntax performance in this corpus.
- Association type and multiplicity are common semantic failure categories.
- Prompt design and human evaluation affect results.
- No universal winner is established.

## Not supported

- Generated diagrams are correct or complete by default.
- Syntax validity proves domain fidelity.
- The descriptively best model on one metric is generally superior.
- The results establish current 2026 model performance.
- The results generalize to industrial, security or privacy requirements.
- The workflow produces complete traceability or reliable change propagation.
- The workflow can replace experienced modelers.
- Apollon JSON is a trustworthy neutral Base Analysis.

## Relationship with Documentation-Driven Threat Analysis

### Candidate lifecycle

```text
governed requirements
-> selected assertions and exclusions recorded
-> generation context and provenance frozen
-> candidate Apollon JSON / UML generated
-> schema and syntax validation
-> source-coverage validation
-> structural-semantic and domain validation
-> trace validation
-> human review
-> accepted | corrected | rejected | deferred
-> stale after source, prompt, model, context or acceptance-rule change
-> regenerate and re-review
```

### Required plugin contract

A model-generation plugin should declare:

- accepted document and requirement types;
- selected assertions, exclusions and preprocessing;
- provider, model ID, snapshot and interface/API version;
- complete system/user prompt and few-shot examples;
- parameters, session state, retrieval context and timestamp;
- output schema, notation and renderer version;
- proposed classes, attributes, methods, relations and hierarchies;
- proposed source-to-element traces;
- omitted, added, contradicted and abstracted content;
- schema and syntax results;
- source-coverage result;
- structural-semantic and domain-validation result;
- alternatives, variability and corrections;
- reviewer, disposition and stale triggers.

### Thesis implication

A class diagram may be syntactically clean and cover many source concepts while assigning the wrong
association, containment or multiplicity. DDTA must preserve the source as authority and treat the
diagram as a replaceable reviewed projection.

## Candidate thesis claims

Supported directly or conditionally:

- Multi-model comparison confirms that quality is multidimensional and model-dependent.
- Syntax, source coverage and semantic correctness require separate evidence.
- Association and multiplicity validation are mandatory for generated class diagrams.
- A provider-level model choice cannot substitute artifact-level acceptance.
- Provider/model/prompt/session provenance is required for reproducibility and change control.

Not supported:

- DDTA can construct a trustworthy structural model from one prompt without review.
- One LLM is universally best for requirements-to-UML generation.
- Educational class-diagram results establish industrial threat-model quality.
- Generated structural models automatically cover security-relevant facts.
