\subsection{2. BA5 objective - canonical semantic registry and
controlled
authoring}\label{ba5-objective---canonical-semantic-registry-and-controlled-authoring}

BA5 uses a strict authoring hypothesis:

\begin{Shaded}
\begin{Highlighting}[]
\NormalTok{registered canonical token}
\NormalTok{    {-}\textgreater{} normative semantic authoring}

\NormalTok{unregistered alias / synonym}
\NormalTok{    {-}\textgreater{} not silently equivalent}
\end{Highlighting}
\end{Shaded}

The purpose is to make cross-document, Base Analysis and projection
integration deterministic before considering lexical normalization as
optional future assistance.

\subsection{3. BA5-T1 result}\label{ba5-t1-result}

T1 establishes one exact canonical referent name per governed
baseline/naming scope, rejects aliases as second normative entity
identifiers and preserves BA3 semantic identity across a governed
rename.

\begin{Shaded}
\begin{Highlighting}[]
\NormalTok{canonicalName != BAReferent identity}
\end{Highlighting}
\end{Shaded}

Shared projections use the canonical referent name when presenting that
shared entity; method-owned types/aggregations may retain local labels.

\subsection{4. BA5-T2 result}\label{ba5-t2-result}

T2 extends exact-token discipline across BA2 vocabulary and finds five
refinements.

\subsubsection{4.1 Domain-scoped
registries}\label{domain-scoped-registries}

One flat global token namespace is rejected. Registry lookup preserves
semantic domain and, for roles, operator context.

\subsubsection{4.2 Exact BA2 keys}\label{exact-ba2-keys}

All thirteen operators remain exact canonical keys. Roles resolve as:

\begin{Shaded}
\begin{Highlighting}[]
\NormalTok{(semanticOperatorKey, roleKey)}
\end{Highlighting}
\end{Shaded}

\subsubsection{4.3 Extensible domains}\label{extensible-domains}

\texttt{semanticKind} and controlled reusable value domains may admit
new method-neutral entries when evidence proves a genuine distinction.
They do not require a universal pre-enumerated taxonomy.

Current T2 pressure explicitly covers:

\begin{Shaded}
\begin{Highlighting}[]
\NormalTok{store  contract}
\NormalTok{affirmative  negative}
\NormalTok{condition  temporalScope}
\NormalTok{ownership  management}
\end{Highlighting}
\end{Shaded}

\texttt{channel} remains DEFERRED / EVIDENCE-GATED rather than being
promoted for convenience.

\subsubsection{4.4 Immutable revision
resolution}\label{immutable-revision-resolution}

Mutable registry definitions are rejected. Extensible and
methodology-contract registries resolve through immutable revisions;
referent names remain anchored to governed documentation
baselines/naming scopes.

\subsubsection{4.5 Extension routing}\label{extension-routing}

\begin{Shaded}
\begin{Highlighting}[]
\NormalTok{alias {-}\textgreater{} reject/use existing key}
\NormalTok{method{-}specific {-}\textgreater{} keep downstream}
\NormalTok{needs independent identity {-}\textgreater{} BAReferent}
\NormalTok{genuine extensible{-}domain entry {-}\textgreater{} governed registry revision}
\NormalTok{genuine new operator/role contract {-}\textgreater{} smallest BA2 reopen}
\end{Highlighting}
\end{Shaded}

No normative synonym table is forced.

\subsection{5. BA5-T3 - canonical registry, controlled-authoring and
no-synonym closure
review}\label{ba5-t3---canonical-registry-controlled-authoring-and-no-synonym-closure-review}

\textbf{NEXT / NOT EXECUTED BY THIS PLAN REVISION.}

BA5-T3 must perform one integrated adversarial closure review over T1
and T2.

It must pressure-test at least:

\begin{enumerate}
\def\labelenumi{\arabic{enumi}.}
\tightlist
\item
  the complete registry-set boundary without collapsing all tokens into
  one namespace;
\item
  referent canonical-name consistency together with a governed
  cross-baseline rename;
\item
  immutable registry revision change while historical BA/projections
  remain reproducible;
\item
  exact operators and operator-scoped roles across facial and order/WMS
  examples;
\item
  extensible \texttt{semanticKind} / controlled-value admission versus
  closed BA2 contract changes;
\item
  a human projection plus two incompatible methodology projections
  without method taxonomy entering BA;
\item
  alias/synonym attempts at referent, operator, role, semantic-kind and
  controlled-value levels;
\item
  tool validation/completion/extension-request assistance without
  semantic-authority leakage;
\item
  whether any material counterexample forces synonym support; and
\item
  whether any BA5 responsibility forces the smallest BA1-BA4 reopen.
\end{enumerate}

\subsubsection{BA5-T3 guardrails}\label{ba5-t3-guardrails}

Do not:

\begin{itemize}
\tightlist
\item
  build a synonym ontology by default;
\item
  perform arbitrary-narrative migration;
\item
  authorize NLP/LLM output as semantic truth;
\item
  define a universal semantic-kind taxonomy;
\item
  promote method-specific terminology into Base Analysis;
\item
  change closed BA2 operators/roles through a lexical registry
  extension;
\item
  define ThreatForge classes/tables/UI;
\item
  start BA6;
\item
  define AnalysisRecord/Common Finding or formal STRIDE/STRIDE-AI
  schemas.
\end{itemize}

\subsubsection{BA5-T3 exit condition}\label{ba5-t3-exit-condition}

If no material counterexample survives, close BA5 for current thesis
scope and freeze the smallest canonical-registry/controlled-authoring
contract with explicit reopen criteria.

If a material counterexample survives, reopen only the smallest affected
BA5 or earlier semantic responsibility.
