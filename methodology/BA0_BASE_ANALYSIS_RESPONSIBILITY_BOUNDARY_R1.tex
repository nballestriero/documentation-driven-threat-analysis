\section{DDTA Base Analysis responsibility boundary -
R1}\label{ddta-base-analysis-responsibility-boundary---r1}

\textbf{Status:} CLOSED BY BA0-T3

\textbf{Repository baseline reviewed:}
\texttt{ced13f9329c89c759b3608d66c3f81ac79b9469b}

\textbf{Activation:} applies when the BA0-T3 closure package is accepted
and committed.

\textbf{Authority note:} this artifact defines the analysis-layer
responsibility boundary; governed project documentation remains project
authority.

\subsection{Responsibility statement}\label{responsibility-statement}

For a governed documentation baseline, \textbf{Base Analysis is the
accepted methodology-neutral analytical representation of the shared
project meaning required by DDTA}. It preserves baseline-scoped semantic
identity, source/origin provenance and explicit unresolved state
sufficiently to support reproducible reuse, progressive human and
method-specific projections, source drill-down, change-impact reasoning
and source-localized feedback handoff.

Base Analysis may normalize and derive analytical structure from
governed meaning, but it must not silently create project commitments.
Method-specific interpretation and analysis output remain outside the
shared core. The representation may be reused or reproducibly rebuilt;
semantic canonicality does not require one permanently materialized
graph or implementation technology.

\subsection{Closed responsibilities}\label{closed-responsibilities}

\begin{itemize}
\tightlist
\item
  \textbf{BA0-C1 Authority and provenance boundary:} project facts
  remain grounded in governed documentation; derivation and origin
  remain traceable.
\item
  \textbf{BA0-C2 Baseline-scoped shared semantic identity:} accepted
  referents/propositions remain stable enough for reuse, comparison and
  revalidation.
\item
  \textbf{BA0-C3 Method-neutral shared core:} method-owned semantics
  stay outside the common project-meaning layer.
\item
  \textbf{BA0-C4 Explicit uncertainty and diagnostic localization:}
  encountered conflict, ambiguity, missing information or insufficiency
  is preserved rather than silently resolved.
\item
  \textbf{BA0-C5 Projection readiness and source drill-down:} the same
  semantics support bounded human/method projections and navigation back
  to governed sources.
\item
  \textbf{BA0-C6 Change-impact traceability:} source/semantic/dependency
  links support identification of potentially impacted analytical
  artifacts after change.
\item
  \textbf{BA0-C7 Source-localized feedback handoff:} analysis outputs
  can identify the governed source area needing review without BA
  choosing or governing the correction.
\item
  \textbf{BA0-C8 Minimality and representation independence:} only
  justified shared semantics belong in BA; no storage, notation, graph
  or general-purpose modeling language is mandated.
\end{itemize}

\subsection{Required origin-state
responsibilities}\label{required-origin-state-responsibilities}

At responsibility level BA must distinguish:

\begin{itemize}
\tightlist
\item
  grounded;
\item
  derived;
\item
  diagnostic / unresolved.
\end{itemize}

A general \texttt{reviewed\ analytical\ addition} class is \textbf{not
required by BA0}. Any later proposal for such a shared-core construct
must remain explicitly non-project-authoritative and may reopen BA0 if
it changes the responsibility boundary.

\subsection{Closed non-goals}\label{closed-non-goals}

Base Analysis is not:

\begin{itemize}
\tightlist
\item
  project documentation authority or the document-governance workflow;
\item
  an automatic arbitrary-narrative extraction/migration engine;
\item
  a mechanism for silently promoting LLM/NLP/tool inference;
\item
  a universal contradiction detector;
\item
  a pre-approved BAE taxonomy or relation vocabulary;
\item
  a SysML/KerML/ArchiMate/AADL replacement;
\item
  a STRIDE/STRIDE-AI model or universal threat ontology;
\item
  AnalysisRecord, Common Finding or Finding acceptance;
\item
  the owner of corrective project decisions;
\item
  a mandatory persisted graph/database/serialization/diagram;
\item
  a proof of visualization usability;
\item
  a downstream re-analysis scheduler.
\end{itemize}

\subsection{Deferred representation
questions}\label{deferred-representation-questions}

BA1-BA6 decide how the closed responsibilities are represented,
materialized, projected and regressed. BA0 closure accepts no BAE type
or relation.

\subsection{Reopen rule}\label{reopen-rule}

BA0 is reopened only by a material responsibility-level counterexample,
not by ordinary ontology, relation, storage or rendering choices.
