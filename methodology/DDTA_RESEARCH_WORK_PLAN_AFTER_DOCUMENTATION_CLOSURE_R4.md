## 2. Scope correction carried into R4

## 3. Base Analysis responsibility now under test

Base Analysis is the accepted methodology-neutral analytical boundary that should support, from the same governed project meaning:

- progressive human comprehension and drill-down;
- shared identity/provenance across analyses;
- method-specific projections without core contamination;
- localized diagnostics for missing/ambiguous/inconsistent information;
- governed corrective feedback;
- change-aware revalidation and targeted re-analysis.

Semantic canonicality does not imply one permanently materialized graph.

## 5. Sequence after BA0 closure

Do not skip phases:

```text
BA1 - Minimal BAE ontology
BA2 - Relations and canonical action vocabulary
BA3 - Document-to-BAE derivation, provenance and authority
BA4 - Multi-level human and method projections
BA5 - Controlled vocabulary and optional authoring/extraction assistance
BA6 - Base Analysis closure and regression
```

### BA1 - Minimal BAE ontology

Start from responsibilities forced jointly by governed DDTA corpora, BA0-R evidence and BA0 trials. No type from historical `primary-analysis-focus` studies, STRIDE, SysML, ThreatForge or another notation is accepted by default.

### BA2 - Relations and canonical action vocabulary

Define the smallest stable semantic relation vocabulary. Keep semantic relation, canonical lexical label and authoring synonym assistance separate.

### BA3 - Document-to-BAE derivation, provenance and authority

Close identity, source locators, grounded/derived/reviewed-addition boundaries, acceptance/rejection, stale state and document-to-analysis traceability. Automatic candidate extraction may be evaluated as optional assistance but is not required for thesis validity.

### BA4 - Multi-level human and method projections

Views are derived from the same accepted Base Analysis semantics, whether the representation is reused or reproducibly rebuilt. Test both progressive human teachability and analysis-specific views. No view is source authority.

### BA5 - Controlled vocabulary and optional assistance

Vocabulary reuse, duplicate suggestions, LLM/NLP proposals and candidate extraction are optional support. None may silently establish identity, equivalence, ownership, project fact or BAE acceptance.

### BA6 - Base Analysis closure and regression

Regress closed corpora and at least one structurally different holdout. Verify semantic identity stability, source traceability, projection consistency, diagnostic behavior, change/re-analysis scope, method neutrality and human drill-down support.

## 8. Corrective feedback boundary

The general DDTA loop is broader than `Finding -> SecurityRequirement`:

```text
analysis / validation / diagnostic
 -> source-localized corrective candidate
 -> governed review
 -> correction / clarification / supersession / new requirement or decision
 -> Base Analysis revalidation
 -> impacted re-analysis
```

The thesis may still evaluate the narrower accepted security-Finding-to-SecurityRequirement path as a specific research contribution. BA0 must not assume every correction has the same document type.
