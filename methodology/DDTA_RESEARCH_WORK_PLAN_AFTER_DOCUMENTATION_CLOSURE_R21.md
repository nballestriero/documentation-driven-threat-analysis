## 2. BA5 objective - canonical semantic registry and controlled authoring

BA5 uses a strict authoring hypothesis:

```text
registered canonical token
    -> normative semantic authoring

unregistered alias / synonym
    -> not silently equivalent
```

The purpose is to make cross-document, Base Analysis and projection integration deterministic before considering lexical normalization as optional future assistance.

## 3. BA5-T1 result

## 4. BA5-T2 result

T2 extends exact-token discipline across BA2 vocabulary and finds five refinements.

### 4.1 Domain-scoped registries

One flat global token namespace is rejected. Registry lookup preserves semantic domain and, for roles, operator context.

### 4.2 Exact BA2 keys

All thirteen operators remain exact canonical keys. Roles resolve as:

```text
(semanticOperatorKey, roleKey)
```

### 4.3 Extensible domains

`semanticKind` and controlled reusable value domains may admit new method-neutral entries when evidence proves a genuine distinction. They do not require a universal pre-enumerated taxonomy.

Current T2 pressure explicitly covers:

```text
store  contract
affirmative  negative
condition  temporalScope
ownership  management
```

`channel` remains DEFERRED / EVIDENCE-GATED rather than being promoted for convenience.

### 4.4 Immutable revision resolution

Mutable registry definitions are rejected. Extensible and methodology-contract registries resolve through immutable revisions; referent names remain anchored to governed documentation baselines/naming scopes.

### 4.5 Extension routing

```text
alias -> reject/use existing key
method-specific -> keep downstream
needs independent identity -> BAReferent
genuine extensible-domain entry -> governed registry revision
genuine new operator/role contract -> smallest BA2 reopen
```

No normative synonym table is forced.
